Guides / Quickstart

Bắt đầu tích hợp

Lộ trình ngắn để hiểu và thử hợp đồng API trong một môi trường local được cấp quyền. Đây không phải hướng dẫn truy cập Backend công khai vì DX-OS chưa cung cấp public production API.

Trạng thái ứng viênBackend Java Helpdesk (PR #74) và Swagger/OpenAPI (PR #79) vẫn ở trạng thái draft. Người dùng chỉ nên thử gọi API trên môi trường disposable riêng với tài khoản Keycloak thật đã provision đúng tenant.
01 / Setup

Quickstart theo bốn bước

  1. Chuẩn bị local environment

    Java 21, Docker Desktop Linux engine, PostgreSQL disposable và Keycloak. Dùng runbook của repository, không dùng một database staging hoặc production.

  2. Định danh ba actor có thật

    Employee, Coordinator, Worker phải là tài khoản Keycloak khác nhau, có issuer/sub hợp lệ và membership/role được provision trong tenant demo. Thiết lập database không có actor (ACTORS=0) chưa đủ để thử quy trình.

  3. Kiểm tra tài liệu và hợp đồng

    OpenAPI JSON local tại /v3/api-docs/it-helpdesk-mvp khi opt-in; Swagger UI chỉ trên loopback. Trên máy demo đã có kiểm tra 9 route và các HTTP 401 cơ bản.

  4. Gọi API bằng access token được cấp hợp lệ

    Backend phải kiểm tra JWT, tenant, ACL, vai trò, trạng thái và phiên bản trước khi cho phép thao tác. Không lấy token từ screenshot, issue hoặc log.

02 / Identity & authorization

Keycloak JWT không thay ACL

Xác thực và phân quyền là hai việc khác nhau.

◎

Identity

Keycloak xác nhận danh tính và phát hành access token. Backend xác minh chữ ký, issuer, audience, kiểu token và hạn sử dụng.

▣

Authorization

Backend quyết định theo tenant membership, operation authorities, độ hiển thị tài nguyên, ACL và quyền theo trạng thái Workflow. Token đúng không đồng nghĩa được đọc mọi request.

HTTP · Chỉ minh họa hợp đồng, không phải lệnh chạy sẵn
GET {BASE_URL}/api/v1/mvp/requests
Authorization: Bearer {ACCESS_TOKEN}
Accept: application/json

{BASE_URL} phải là địa chỉ Backend riêng được tổ chức cấp quyền. Website này không cung cấp public API endpoint; không dán token thật vào các form công khai.

Trường hợp không thấy tài nguyênBackend có thể trả 404 cho tài nguyên không tồn tại, bị ẩn hoặc thuộc tenant khác. 403 chỉ dùng khi tài nguyên đã được phép nhìn thấy nhưng thao tác bị cấm, tùy contract/mapping.

Ví dụ phân công

Không tự chế assigneeId; hãy dùng actor ID thật từ eligibleAssignees của response được phép đọc.

{
  "assigneeId": "{CANONICAL_ACTOR_ID}",
  "expectedAssignmentVersion": 0
}
