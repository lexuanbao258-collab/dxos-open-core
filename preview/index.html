02 / Interface

API surface

Cả 9 route đều nằm dưới /api/v1/mvp/requests. Đăng nhập không tự động cấp quyền xem hoặc sửa một request.

MethodEndpointChức năng
GET/requestsDanh sách yêu cầu được phép xem
POST/requestsEmployee tạo yêu cầu
GET/requests/{id}Đọc chi tiết và allowedActions
GET/requests/{id}/historyXem lịch sử chuyển trạng thái
POST/requests/{id}/triageCoordinator tiếp nhận
POST/requests/{id}/assignCoordinator phân công
POST/requests/{id}/startWorker bắt đầu xử lý
POST/requests/{id}/resolveWorker ghi nhận kết quả

03 / Build

Ví dụ hợp đồng request

Đây là mẫu body của API tạo yêu cầu, không phải request thực tế đã gửi đến server.

JSON · POST /api/v1/mvp/requests
{
  "title": "Máy tính không kết nối Internet",
  "description": "Máy tính phòng học không truy cập được mạng.",
  "requestType": "IT_HELPDESK"
}

Response dự kiến khi tạo thành công: HTTP 201, request ở trạng thái SUBMITTED và Workflow version=0. Backend vẫn kiểm tra token, tenant và quyền tạo.

04 / Engineering

Những điều DX-OS ưu tiên

⊞

Resource-level ACL

Không dùng mỗi vai trò để quyết định có được nhìn thấy tài nguyên hay không.

⟳

Version guards

Workflow version và assignment version riêng biệt để ngăn cập nhật dựa trên dữ liệu cũ.

◇

Source over claims

Tài liệu liên kết nguồn; kiểm thử local không được diễn giải thành production readiness.
